# AI risk assessment

Model-specific failure modes, the control that addresses each one, and the test that proves
the control exists. A risk with no control is listed as accepted, not quietly omitted.

The distinction this table is built around: **a control is code or a test. A warning in a
README is a disclosure, not a control.** Both appear below, labelled honestly.

| ID      | Failure mode                                                                                | Why it matters to a product decision                                                     | Control                                                                                                                                                                                           | Type              | Proof                                                                                                                           |
| ------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| RISK-01 | Model fabricates a quotation that no reviewer wrote                                         | A PM cites invented customer evidence in a roadmap review                                | Server re-checks every model-supplied quote against the owned source text and drops findings that fail (`r.text.includes(f.quote)`)                                                               | Code              | `app/api/workspace/route.ts`; test: _semantic indexing is resumable and AI citations are validated_                             |
| RISK-02 | Retrieved examples are read as prevalence — "5 reviews mention this, so it's the top issue" | The single most common way review tooling misleads a roadmap                             | Counts and rankings are computed deterministically over the full scoped set and never from retrieved examples, in all three modes                                                                 | Code              | `lib/reviewlens/intelligence.ts`; test: _prevalence counts all relevant reviews regardless of retrieved example count_          |
| RISK-03 | Review text contains prompt injection                                                       | A malicious reviewer steers the answer shown to the product team                         | Reviews are passed as JSON data with a system instruction to treat them as untrusted; output is constrained to `{findings, abstain}` and every finding is quote-verified against source (RISK-01) | Code              | Injection string is row 20 of the demo corpus (`lib/reviewlens/demo.ts`); acceptance case _Prompt extraction_                   |
| RISK-04 | Model answers confidently when the corpus contains no evidence                              | Absence of evidence is reported as evidence of absence                                   | Explicit `abstain` path; `status: 'unsupported'` and `'clarify'` intents; absent-topic false-positive rate is a gated metric in `npm run eval`                                                    | Code + gate       | `eval/thresholds.json` → `absent_topic_false_positive_rate`; acceptance cases _Unknown topic_, _Unknown percentage_             |
| RISK-05 | Similarity score is read as a confidence score                                              | 0.31 cosine looks like 31% certainty to a non-specialist                                 | Retrieval results are labelled "limited evidence"; the 0.30 cutoff is documented as an uncalibrated heuristic, not a probability                                                                  | Code + disclosure | `lib/reviewlens/device-answer.ts` notes; [DEC-04](decision-log.md)                                                              |
| RISK-06 | Client-supplied ranking is trusted by the server                                            | A tampered browser injects text or out-of-scope reviews into a saved answer              | Server re-filters candidates to the owned, scoped set and accepts only exact substrings of owned review text; caps at 5, de-duplicates                                                            | Code              | `lib/reviewlens/device-answer.ts`; test: _device evidence works without a paid key or budget and is saved with validated scope_ |
| RISK-07 | Tenant isolation rests on an unauthenticated request header                                 | Any reader of any tenant's customer reviews, if the app is reachable without its gateway | Deployment must assert a trusted gateway via `IDENTITY_GATEWAY`; the API returns 503 rather than trusting the header                                                                              | Code              | `lib/reviewlens/server.ts`; test: _API refuses to attribute ownership when no identity gateway is declared_                     |
| RISK-08 | Provider cost runs away through retries or abuse                                            | An unbounded bill on a personally funded API account                                     | Budget is consumed **before** the outbound call, capped at 100 requests/user/UTC day, failures included                                                                                           | Code              | `lib/reviewlens/server.ts` `consumeBudget`; test: _daily budget blocks provider requests before an external call_               |
| RISK-09 | Customer review text leaves the device to a third party without the user understanding it   | Privacy expectation mismatch; potential PII in free-text reviews                         | Three modes are named and separated in the UI by mechanism and cost; OpenAI mode requires the user's own key; on-device mode makes no per-request external call                                   | Disclosure + code | Mode table in [README](../../README.md); `lib/reviewlens/device-client.ts`                                                      |
| RISK-10 | English rule-based theme labels silently miss non-English, sarcasm or unfamiliar domains    | Under-counted complaints read as "not a problem"                                         | Coverage percentage is surfaced with every ranking; "unclassified does not mean positive" is stated in answer notes                                                                               | Disclosure        | `lib/reviewlens/intelligence.ts` notes; [RISK-03 in RAID](raid-log.md)                                                          |

## Accepted, uncontrolled

Stated plainly because pretending otherwise would be the actual risk.

| ID     | Risk                                                         | Why it is accepted                                                                                                                | What would change that                                                                                 |
| ------ | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| ACC-01 | Retrieval quality of the on-device model is unmeasured       | The model has never run in a browser in any environment available to me                                                           | Completing [the on-device UAT](uat-on-device.md) and feeding captured hits to `npm run eval -- --hits` |
| ACC-02 | Golden set has one annotator and 24 reviews                  | Sufficient as a regression gate; insufficient as an accuracy claim                                                                | A second annotator, inter-annotator agreement, and a corpus in the hundreds                            |
| ACC-03 | Generated-answer faithfulness is unmeasured against a rubric | No funded provider evaluation was run; quote-verification (RISK-01) bounds the damage but does not measure interpretation quality | A labelled faithfulness rubric scored over held-out questions                                          |
| ACC-04 | No PII detection or redaction on import                      | Out of scope for a portfolio corpus of fictional reviews; would be a launch blocker for real customer data                        | Any use with real review data                                                                          |
| ACC-05 | Dataset is fully loaded into Worker memory per question      | Correct and simple at the documented 2,000-review ceiling                                                                         | Raising the ceiling — see [DEC-07](decision-log.md)                                                    |

## How this was used

Each control above was written because a specific failure was anticipated, not discovered.
RISK-01 and RISK-02 shaped the API contract before the UI existed: the server returns
`findings` with `reviewIds`, and statistics are a separate field from evidence, so the two can
never be conflated by a caller. RISK-07 was the finding of a review pass over the shipped
code, and produced the one behavioural change in this revision — the API now refuses to serve
an ungated deployment instead of documenting that it should not be deployed that way.
