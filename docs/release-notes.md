# ReviewLens browser release

## Product decisions

- Publish privately with persistent user ownership. Public registration and multi-tenant billing are outside this release.
- Preserve the original uploaded source archive; port the working surface and services to the hosting runtime.
- Separate corpus statistics from retrieved examples. Theme ranks count distinct reviews across the selected scope; each review contributes once per theme.
- Use the full selected review count as the default share denominator, including unrated reviews. Average rating excludes unrated records. An explicit “percentage of one-star reviews mentioning …” uses that rating subset as its denominator.
- Support English review text and an explicit feature catalogue. Expose limitations rather than advertising rule-based labels as ML.
- Offer genuine model embeddings and grounded generation through a user-owned provider key, encrypted at rest. Default operation is deterministic and incurs no provider cost.
- Retain raw quotation evidence and traceability; remove arbitrary numeric confidence scores.

## Fixed regressions

The shipped demo is generated by one CSV writer and parses 20 reviews without column drift. Invalid CSV columns, invalid dates, NaN ratings and unmapped review text are handled before storage. Core complaint questions return prevalence; two-star percentages return the requested statistic. Natural-language scopes are checked against metadata, and conflicts clarify rather than silently widening the query. Stale answer requests are cancelled or ignored after scope changes. Deletion is confirmed and ownership checked.

## Verification scope

All 24 domain and API integration tests pass. The in-app evaluation separately runs 24 distinct synthetic questions with independently specified expected values. API tests exercise the actual route with a D1-compatible database: unauthenticated and cross-owner access, imports, idempotency, persisted history, feedback, encryption, evaluation and deletion cascades. Simulated provider responses verify resumable semantic indexing, source-quote validation, token accounting and the daily request cap. Type checking and the production build pass. These are acceptance checks, not a statistical claim of production AI accuracy.

Live paid-provider quality is not verified without an account key. The optional model path checks exact quotes against source text; it does not independently establish claim entailment. No browser visual QA was requested. Hosted publication status verifies deployment, not real customer usability.

## Operating limits

2,000 reviews/dataset, 2 MB uploads, 20 datasets/user, 100 provider calls/day/user. Index batches can resume after failure. Original CSV/JSON files are not kept as separate blobs. The app shows raw provider token counts, not monetary billing estimates. Keep source data outside ReviewLens; backup restore is not implemented.

## Suggested next evidence

Evaluate on independently labelled customer datasets, including unseen products and subtle negation, before expanding the supported domains. Measure useful-answer rate, reviewer agreement, per-question costs, latency and source verification time. Do not represent synthetic acceptance scores as real-world model accuracy.
